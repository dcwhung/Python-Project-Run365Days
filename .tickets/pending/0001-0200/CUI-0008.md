## 問題描述

`src/common/geo.py:31` 收到非有限座標時，numpy 只會發
`RuntimeWarning: invalid value encountered in sin/cos`，然後回一個 `nan`，
唔會拒絕輸入。

## 可達性

**經 GPX / KML 已唔可達** —— CUI-0001 已將兩者嘅 lat / lon 讀取硬化成
`parse_finite_float()`。但 `haversine_distance` 係 public function，
in-process caller 仍然可以直接餵 inf / nan 落去。

CUI-0001 修復前實測：`lat_inf_2102.gpx` 令 `distance_by_coord_km = 0.0` —— **靜默**，
就係經呢條 sin/cos 路徑。

## 建議修復方向

於 `haversine_distance` 入口加有限性檢查，非有限即掟明確錯誤而唔係回 `nan`。
留意佢係 hot path（`total_track_distance` 逐點呼叫），檢查要用向量化做法，
唔好逐點 Python-level 檢查 —— 順帶參考 AU-039（該函數而家用 `DataFrame.apply()`
逐點算，本身已經係最慢寫法）。

## 驗證方式

- 直接餵 `inf` / `nan` 座標，得到明確錯誤而非 `nan`
- 365 個真實檔案 export 後 static JSON 仍然 byte-identical
- 209 條現有測試全綠
