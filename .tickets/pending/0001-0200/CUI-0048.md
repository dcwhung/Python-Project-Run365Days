# CUI-0048 `service.tracks` 個 negative guard 漏咗 `-0.0`，而 `2.5` 掟一個未記錄嘅 `TypeError`

**狀態**：✅ done
**類型**：bug / contract
**優先級**：🟢 Low
**來源**：QA 2026-09-17（CUI-0040 主動測試）
**建立日期**：2026-09-17
**建立人**：Main Agent（由 QA Agent 發現）
**負責人**：Backend Developer
**相關**：CUI-0040（加咗個 guard）、CUI-0033 (a)、CUI-0025

---

## 問題描述

CUI-0040 個 guard 係 `if points is not None and points < 0: raise ValueError(...)`。

**`-0.0 < 0` 係 `False`**，所以 `-0.0` 唔 raise。而 `-0.0` 係 falsy，行落
`min(points, MAX_TRACK_POINTS) if points else MAX_TRACK_POINTS` 個 else 分支
⇒ **回成條 track**（QA 對住 `7264441638` 實測 **600 行**）。

同一個函數 `-0.5` 同 `-1` 都正確 raise。

另外 `points=2.5` 掟 `TypeError: 'float' object cannot be interpreted as an integer`
（由 sampler 深處掟出），但 docstring 個 `Raises:` 只寫咗 `ValueError`。

## QA 實測表

| `points` | 結果 |
|---|---|
| `-1` / `-0.5` | ✅ `ValueError` |
| **`-0.0`** | ⚠️ **600 行**（當「冇問過」）|
| `0` / `None` / `False` | 600 行（符合設計）|
| `True` / `1` | 1 行 |
| `1000` / `10**9` | 600 行（cap 生效）|
| **`2.5`** | ⚠️ `TypeError`（docstring 冇寫）|
| **空 id list + `-1`** | ✅ **仍然 raise**（guard 排喺 early-return 前）—— 呢條冇人測過 |

## 影響

🟢 Low，**到唔到 client**：`schema._track_points`、`static/source.ts` 個 `checkPoints`、
同 GraphQL `Int` coercion **三重**都先 refuse。純粹係 public module-level function 嘅契約整潔。

## 建議

- Guard 改 `not (points > 0)`（同時收 `-0.0`），**或者**喺 docstring 明文寫低 `-0.0` 當 `0` 處理
  —— 兩個都得，但要揀一個並寫低理由（CUI-0040 當初就係為咗「`0` 同 `-5` 語意唔同」而揀 raise 唔 clamp）
- `Raises:` 補 `TypeError`，或者收窄成 `ValueError`

## 驗證方式

- `tracks(s,[id],-0.0)` 同 `tracks(s,[id],2.5)` 各有一條測試釘住揀咗嘅決定
- 順手補一條釘住 `tracks(s,[],-1)` 仍然 raise（guard 排喺 early-return 前呢個性質）
