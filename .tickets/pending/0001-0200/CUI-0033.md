## (a) 🟡 `undefined` 分支唔受 `MAX_TRACK_POINTS` 管，而個 bound 只係兩個常數啱啱相等

CUI-0025 決定 2 保留 static mode「`points` omitted = 回全部」，理由係
「the export caps a track at 600 rows, so "all of it" is bounded by construction」。

**個 600 唔係結構，係 `src/cli/export_data.py:27` `DEFAULT_POINT_LIMIT` 呢個 CLI argument 嘅 default。**

QA 用**真實數據**行咗一次 `run365-export --points 1200`（365 條真 activity，輸出落 scratch，
`data/processed/` 由頭到尾冇被寫過）：

| 量度 | 預設 export（`--points` 600） | `--points 1200` |
|---|---|---|
| 超過 600 行嘅 track | 0 / 365 | **2 / 365** |
| 最長一條（activity `7264441638`） | 600 行 | **1200 行** |

跟住用**真 `createStaticSource`**（唔係手砌 fixture，真 fetcher 讀真 JSON）同
**真 Flask + Strawberry**（`create_app` + `/api/graphql`）各打一次同一個 activity：

| 叫法 | static mode | api mode（`createApiSource`）|
|---|---|---|
| `track(id, 1200)` | ❌ `RangeError: points must be between 1 and 1000, got 1200` | ❌ 同一句 |
| `track(id, 1000)` | ✅ 1000 點 | ✅ 1000 點（逐點一樣）|
| **`track(id)`（omitted）** | ⚠️ **1200 點** | **600 點**（`DEFAULT_TRACK_POINTS`）|

兩個後果：

1. **Mode 分歧原樣返嚟**：1200 vs 600 —— 即係 CUI-0025 想關嗰種分歧，換咗個入口（`--points`）。
2. **個 ceiling 唔係輸出嘅 ceiling**：同一個 function 會**拒絕**「畀我 1200 點」，
   但**照回** 1200 點畀一個冇講數量嘅 caller。`MAX_TRACK_POINTS` 只係「你可以問幾多」嘅上限，
   唔係「你會收到幾多」嘅上限，而 docstring 冇講過呢個分別。

> ⚠️ Reviewer 開 S-061 嗰陣係**推論**呢件事；本票係喺**真實 export 上實測到**，
> 包括「1200 > 1000」呢個 S-061 冇提到嘅第二層。

### 建議方向（由 developer 判斷）

- **方案 A（最平，S-061 方案 A）**：只改 `track()` 註釋，寫明依賴 `--points` 而且 omitted 唔受上界管。
  Trade-off：分歧照喺，下一個人要自己記住。
- **方案 B（S-061 方案 B）**：`undefined` 分支套 `DEFAULT_TRACK_POINTS`，兩個 mode default 一致。
  Trade-off：**第二個 breaking change**，而且用戶已拍板「omitted 回全部」—— 要用戶再拍板先做得。
- **方案 C（QA 傾向）**：`undefined` 維持「回全部」（尊重用戶決定），但喺 `downsample` 之前
  用 `MAX_TRACK_POINTS` 封頂，即 omitted = 「全部，最多 1000 點」。
  咁「個 ceiling 係輸出嘅 ceiling」就成立，而今日（stored ≤ 600）行為**零改變**，唔係 breaking change。
  Trade-off：`--points 1200` 之下兩個 mode 仍然係 1000 vs 600，分歧收窄但未消失。

## (b) 🟢 兩個 mode 對同一個非法值講唔同句子

CUI-0025 決定 3 寫明「錯誤形態**逐字一樣**」。QA 逐個值實測（static = 真 `createStaticSource`，
api = 真 Flask + GraphQL）：

| `points` | static mode | api mode | 一致？ |
|---|---|---|---|
| `-1` | `points must be between 1 and 1000, got -1` | 同一句 | ✅ |
| `0` | `... got 0` | 同一句 | ✅ |
| `1001` | `... got 1001` | 同一句 | ✅ |
| `2.5` | `... got 2.5` | `Int cannot represent non-integer value: 2.5` | ❌ |
| `2147483648` | `... got 2147483648` | `Int cannot represent non 32-bit signed integer value: 2147483648` | ❌ |

**拒絕與否完全一致**，只係句子唔同：後兩行喺 api mode 係俾 GraphQL 嘅 `Int!` coercion
喺入 resolver 之前擋咗，`_track_points` 根本冇被叫過。

`checkPoints` 個 docstring 有提「api mode cannot even express one (its SDL argument is `Int!`)」，
所以非整數嗰行算**已披露**；但**超 Int32** 嗰行冇任何文件提過，
而第一句「Rejects the same values and says the same sentence」讀落係覆蓋成個 domain。

### 建議

改 `checkPoints` docstring 一句，講清楚「same sentence」嘅範圍係
「GraphQL `Int!` 表達得到嘅值」，`Int!` 表達唔到嗰啲兩邊都拒絕但句子唔同。純 docstring，零行為改動。

## (c) 🟢 未知 id + 非法 `points`：一邊掟錯，一邊靜靜回 null

| 叫法 | static mode | api mode |
|---|---|---|
| `track("no-such-activity", 0)` | ❌ `RangeError: points must be between 1 and 1000, got 0` | ✅ `{"activity": null}`，**零 error** |
| `track("no-such-activity", 600)` | ❌ `ENOENT ... tracks/no-such-activity.json` | ✅ `{"activity": null}`，零 error |

成因唔係 bug：static mode 嘅 bounds check **刻意**喺 fetch 之前
（QA 已核實呢個 docstring claim 成立 —— 壞 id + `points: 0` 出 `RangeError` 而唔係 `ENOENT`，
即係真係一個 request 都冇發），而 api mode 個 `activity(id:)` 回 `null` 之後
`track` resolver 根本唔會行。

今日零影響（前端個 id 一定嚟自 `activities` list）。值得記低係因為佢係
「one error path」呢個賣點嘅最後一個窿。

### 建議

文件化即可（同 (b) 一齊喺 `track()` 註釋講）。**唔建議**為咗對齊而改 api mode 嘅 null 行為。
