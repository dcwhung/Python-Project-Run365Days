## 問題描述

CUI-0016 修好 `ActivityView` 嗰陣造咗 `frontend/src/lib/errors.ts` 嘅 `readableError()`，
佢自己個 docstring 寫得好清楚點解要存在：

> `graphql-request` builds `ClientError.message` by serialising the whole response
> **and request**, so rendering it raw spills the GraphQL document and its variables
> onto the page.

但 `readableError` **只用咗喺 `ActivityView.tsx` 一個檔案**。其餘四個 render error 嘅位置
仍然直接吐 `error.message`：

| 位置 | 行 |
|---|---|
| `frontend/src/views/overview/OverviewView.tsx` | `20`（`year.error.message`）、`21`（`activities.error.message`） |
| `frontend/src/views/year/YearView.tsx` | `28`（`year.error.message`） |
| `frontend/src/views/activities/ActivitiesView.tsx` | `67`（`all.error.message`） |

## 實測（2026-09-16，真 Flask server + 真 `createApiSource` call path）

用 `frontend/src/data/api/source.ts` 嘅真實 client 打去 `127.0.0.1:5199/api/graphql`，
令 list row budget 拒絕：

```
REFUSED  4 個 list field + YearQuery 嗰頁 = 4500
  readableError(e)  -> list row budget exhausted: one request may read at most 4000 rows
  raw e.message     -> 601 chars，leaks document? true，leaks variables? false
  raw e.message head-> list row budget exhausted: one request may read at most 4000 rows:
                       {"response":{"data":null,"errors":[{"message":"list row budget
                       exhausted: one request may read at most 4000 rows","locations":
                       [{"line":1,"column":120}],…
```

即係話用戶會喺頁面見到一段 **601–620 字元、由 `{"response":…,"request":…}` 序列化出嚟嘅
JSON blob**，入面坐住成個 GraphQL document 原文。`readableError()` 將同一個 error
收成一句 62 字元、可以睇得明嘅說話。

（本次量到 `leaks variables? false` 係因為觸發用嘅 document 冇 variable；
`ActivitiesQuery` / `WeatherQuery` 等真實 document 帶住 `fromDate` / `toDate` /
`minKm` / `hasGps`，一樣會落入同一個 `JSON.stringify({response, request})`。）

## 同 CUI-0027 嘅關係（點解而家提出）

同 CUI-0016 對 AU-047 嗰個關係一模一樣，逐字對得上：

- 呢個**唔係** CUI-0027 引入 —— 任何網絡失敗 / server 500 一直都會咁。
- 但 CUI-0027 為呢四個位**新增咗一個全新嘅可達成因**：list row budget 被拒。
  被拒嘅 list field 係 non-null type，`data` 整個變 `null`，`graphql-request` 掟 `ClientError`，
  TanStack Query `isError` 亮起 → 直上第 20 / 21 / 28 / 67 行。
- **今日前端撞唔到**：五個 document 每個只帶一個收費 field，各charge 500，budget 係 4000
  （QA 已用真 call path 核實：六個 document 同一個 page load 一齊出，381 ms，零拒絕）。
  所以本票**唔阻 CUI-0027 結案**。
- 但呢個係 **public endpoint**，而且 breaking change 已被接受 ——
  任何第三方 client、或者將來有人喺 `queries.ts` 加 `$limit` variable 開始傳窗口，
  都會令呢條路由「理論可達」變成「實際可達」。

## 預期結果

四個位改用 `readableError(...)`，同 `ActivityView.tsx:78-79` 一致。

## 實際結果

顯示 601–620 字元嘅序列化 blob，入面有成個 document 原文。

## 建議

改四行，全部係同一個 pattern：

```tsx
// before
{year.error.message}
// after
{readableError(year.error)}
```

⚠️ 順帶考慮（由 developer 判斷，唔一定喺本票做）：`readableError` 而家係一個要記得叫嘅
helper，忘記叫就靜靜退化。CUI-0016 之後**三個月內已經漏咗四次**。可以考慮一個 lint 規則、
一個共用 `<QueryError>` component，或者喺 `DataProvider` 嘅 `QueryClient` 層統一 normalise
error，令「忘記」唔再係一個選項。

## 驗證方式

- `grep -rn "error\.message" frontend/src --include=*.tsx | grep -v test` 零命中
- 四個 view 各自有一條 test：query 失敗嗰陣畫面顯示 `errors[0].message` 而**唔含**
  `{"response"` 呢個字串
- `npm run lint` / `npm run typecheck` / `npm test` 全綠
