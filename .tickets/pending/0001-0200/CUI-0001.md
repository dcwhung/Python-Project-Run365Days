## 問題描述

W-005 為 `optional_float()` / `optional_int()` 加咗 `math.isfinite()` 檢查，註釋寫明理由係
「`nan` silently poisons any sum and `inf` poisons any min/max」。

但 TCX 兩個**必填**數值唔行呢條路 —— `src/activities/parsers/tcx.py:106-107` 直接
`float(required_text(...))`，冇任何有限性檢查：

```python
"Time": float(required_text(lap, "ns:TotalTimeSeconds", _NS)),
"Distance": float(required_text(lap, "ns:DistanceMeters", _NS)),
```

同時 `src/export/records.py:64-72` 嘅 `_round()` 只擋 NaN，唔擋 ±inf：

```python
def _round(value, ndigits: int = 1):
    if value is None:
        return None
    try:
        if value != value:  # NaN
            return None
    except TypeError:
        return None
    return round(float(value), ndigits)   # ±inf 直接通過
```

結果係同一個壞檔案，喺兩個部署目標行出兩個唔同結果，而且其中一個係靜默污染。

## 重現步驟

1. 造一個 TCX，lap `<DistanceMeters>inf</DistanceMeters>`（其餘正常）
2. `TCXParser(2021).parse_all(dir)` → 成功 parse，`distance_km = inf`
3. `build_records(...)` → `activity_record["distance_km"] = inf`
4. `write_static_json(records, out)` → **crash**
5. `write_sqlite(records, db)` → **成功**，`activities.distance_km = inf`
6. 對步驟 5 個 DB 發 `{activities{id distanceKm}}` → 成句 query 死

另外兩個變體：

7. lap `<TotalTimeSeconds>inf</TotalTimeSeconds>` → `seconds_to_hhmmss(inf)` 內部
   `int(inf)` 掟 `OverflowError`。`OverflowError` 係 `ArithmeticError` 子類，
   **唔係** `ValueError`，所以 `base.py:146` 嘅 `except ValueError` 接唔到，
   `parse_all` 整個中止，成次 export 死。
8. lap `Time` 或 `Distance` 係 `nan` → pandas `.sum()` 預設 `skipna=True`，
   靜默變成 `0.0`，**冇任何 log**，正正就係 W-005 聲稱要防止嗰件事。

## 預期結果

必填數值同 optional 數值行同一套有限性規則。非有限值應該當作不可讀資料：
`raise ActivityParseError`，喺 `parse_all` 被接住並以 WARNING 記低檔名同原因，
單一壞檔案被丟棄，其餘照 export。兩個 writer 對同一份 records 應該有一致結果。

## 建議修復方向

1. `src/activities/parsers/base.py` 加一個 `required_float()`，內部沿用 W-005 嘅
   `math.isfinite()` 規則，非有限即 `raise ActivityParseError`；`tcx.py:106-107` 改用佢。
   KML `_aggregate_laps` 嘅 `float(row[...].split()[0])` 同 GPX 嘅 `float(lat)` / `float(lon)`
   同樣係無防護必填讀取，一併處理。
2. `src/export/records.py` 嘅 `_round()` 由 `value != value` 改為 `math.isfinite(value)`，
   令 ±inf 同 NaN 一樣映射到 `None` —— 呢個係 defence in depth，即使 (1) 有漏網都唔會炸 writer。
3. `parse_all` 嘅 `except ValueError` 擴闊到 `except (ValueError, ArithmeticError)`，
   保留 W-004 嘅 skip / error 語義分野，唔好返去 `except Exception`。
4. 補測：每個必填數值 × `nan` / `inf` / `-inf`，斷言 `ActivityParseError` + WARNING log
   + 其餘檔案照 parse；再加一條 end-to-end 斷言 static 同 sqlite 兩個 writer 對同一份
   records 唔會分歧。

## 驗證方式

- 造 6 個壞 TCX（`Time`/`Distance` × `nan`/`inf`/`-inf`）連同 1 個正常檔案放同一目錄
