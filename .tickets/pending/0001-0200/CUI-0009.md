## 問題描述

`src/common/numeric.py` 嘅 `to_float()` 用 `float(value)` 轉換，而 `"inf"` / `"-inf"` / `"nan"`
喺 Python 係**合法 float literal** —— 所以佢哋會原樣通過，回傳 ±inf / nan 而唔係 `None`。

受影響嘅兩處都係**直接餵入 writer** 嘅路徑：

- `daily_weather_record()`（HKO 每日 extract）
- `hourly_at()`（每小時天氣）

呢兩處嘅值唔經 `finite()`，所以會重演 CUI-0001 / CUI-0007 嗰個 writer 分歧
（`json.dumps(allow_nan=False)` 崩潰 vs SQLite 存 `Infinity`）。

## 可達性

**目前唔可達** —— HKO 嘅 scraped 資料唔會出 `"inf"` 字串。屬硬化缺口。

## 為何唔喺 CUI-0007 一併修

Developer 明確論證：改 `to_float()` 本身嘅語意會擴大回歸面超出該票 scope，
而且 `to_float()` **同時被 collectors 用緊**（`hko_daily.py`、`hourly.py`），
喺嗰邊 `"inf"` 嘅語意未必想當作 `None`。

## 建議修復方向

**唔好改 `to_float()` 本身。** 喺 `daily_weather_record()` / `hourly_at()` 外面包一層
`finite(to_float(...))` —— 即係喺「準備寫入 writer」呢個明確位置做有限性收斂，
而唔係改一個被多處共用嘅低層 helper 嘅語意。

## 驗證方式

- 餵 `"inf"` / `"nan"` 字串落 HKO daily / hourly 記錄，兩個 writer 都成功且數值一致
- 365 個真實檔案 export 後 static JSON 仍然 byte-identical（6,857,102 bytes / 370 files）
- 現有測試全綠
