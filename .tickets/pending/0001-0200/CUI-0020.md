# CUI-0020 `--year` help text 講錯：實際係下限過濾，唔係「只保留該年」

**狀態**：pending
**類型**：bug（文件 / UX）
**優先級**：🟢 Low
**來源**：S-005 修復過程中由 Backend Developer 申報，Main agent 核實
**建立日期**：2026-09-14

---

## 問題描述

`src/cli/process_activities.py` 嘅 argparse help：

```
--year   Target year; activities from other years are skipped
```

但三個 parser 實際做嘅係**下限**過濾：

```
src/activities/parsers/gpx.py:67   if act_time.year < self.current_year:
src/activities/parsers/kml.py:82   if act_time.year < self.current_year:
src/activities/parsers/tcx.py:67   if act_time.year < self.current_year:
```

即係「早過該年就 skip」，**遲過該年嘅一律保留**。

## 實測

`--year 1999` **保留全部 365 條 2021 年嘅 activity**（因為 2021 ≥ 1999），
而唔係 help text 暗示嘅「只保留 1999 年嘅，其餘 skip」。

Developer 就係因為呢點，喺砌真實零記錄測試案例時要用 `--year 2030` 而唔係 `1999`。

## 影響

純文件 / UX。行為本身冇問題（下限過濾對「2021 挑戰」呢個用途係合理嘅 —— 當年之後補錄嘅檔案唔應該被丟），
但 help text 會令人以為可以用佢揀單一年份。

`export_data.py` 嘅 `--year` 亦要一併核對係咪同一語義。

## 建議修復方向

二擇其一：

- **改 help text**（最小）：例如「Earliest year to keep; activities before it are skipped」
- **改行為**：真係做相等過濾 —— 但**唔建議**，會改變現行 export 結果（365 → 視乎資料），
  而且會打破本 session 每輪守住嘅 byte-identical 基準

⚠️ 如果揀改 help text，順帶檢查 `docs/` 同 `README.md` 有冇同樣講法。

## 驗證方式

- `--year 1999` 同 `--year 2021` 行為一致（都係 365 / 357）—— 並喺 help text 反映到
- 現有測試全綠
- static JSON 仍然 byte-identical
