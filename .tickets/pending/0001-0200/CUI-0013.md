## 三項

### 1. `src/cli/collect_weather.py` 覆蓋率 0%，且用 `print()` 而非 logger

CUI-0010 令三個 collector 由 0% 升到 100%，但**佢哋嘅 CLI 入口仍然係 0%**（33 statements）。
呢個亦係 AU-013（零 logging）喺 CLI 層嘅手足。

⚠️ 注意：`src/cli/` 其他檔案嘅 `print()` 係**合理**嘅（CLI 輸出俾用戶睇），
所以呢條唔係「將所有 print 改 logger」。要分清楚「進度輸出」（print 啱）
同「錯誤 / 跳過紀錄」（logger 啱）。

### 2. `_REQUEST_TIMEOUT` 喺三個 module 各有一份

CUI-0010 為咗留喺 lane scope 內，喺 `hko_daily.py` / `hourly.py` / `warnings.py`
各定義咗一次 `_CONNECT_TIMEOUT_SEC = 5` / `_READ_TIMEOUT_SEC = 30`。

應該收歸 `src/common/config.py`（其他 tunable 都喺嗰度）。一行嘢，但要有個 lane 擁有嗰個檔案。

⚠️ CUI-0010 嘅測試係斷言**要求**（有 bounded pair、connect ≤ 10s、read ≤ 60s）而唔係字面值，
所以收歸唔會撞爛測試 —— 呢個係當時特登咁設計嘅。

### 3. 三個 collector 佈滿 magic index 同 slice literal

`data[2]` / `data[11]`、`tds[9]`、以及 `[:-2]` / `[:-5]` / `[:-1]` 等 slice。

CUI-0010 特登冇動，理由充分：命名佢哋係一次跨越三張票都冇掂嘅行數嘅可讀性重構，
分開做 diff 更易 review。**而家安全咗** —— 解析出嚟嘅值已經被 100% 覆蓋嘅測試釘死。
