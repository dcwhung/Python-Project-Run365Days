**問題描述**

CUI-0029 把 `_charge_list_rows` / `_charge_track_field` 改用 `BudgetExceededError` + `REFUSAL_LOG_LEVEL = INFO`，Vercel 預設 config 下每個 budget refusal 由 2583 bytes 降到 0。但 `_page()`（`limit` / `offset` 出界）同 `_track_points()`（`points` 出界）仍然掟 bare `ValueError`，graphql-core `located_error` 照包、set `original_error`，`StrawberryLogger` 照 `ERROR` + `exc_info`。ERROR ≥ 預設 `WARNING` 門檻，所以喺 Vercel 實際會寫出嚟。

**實測（2026-09-16，真 `api/graphql.py` entry、真 `run365.db`、Vercel 預設 logging、OS 層 fd 2 捕捉）**

| document | 字元 / token | stderr bytes | traceback | 絕對路徑 frame |
|---|---|---|---|---|
| `{ activities(offset: -1) { id } }` | **33 / 7** | **2016** | ✅ | **9** |
| `{ activities(limit: 1001) { id } }` | 34 / 7 | 2046 | ✅ | 9 |
| `{ activity(id:"…"){ track(points: 0){ sec } } }` | 59 / 11 | 2145 | ✅ | 9 |
| `{ activity(id:"…"){ track(points: 1001){ sec } } }` | 62 / 11 | 2154 | ✅ | 9 |
| budget refusal（CUI-0029 已修）| 387 / 72 | **0** | ✗ | 0 |
| introspection refusal | 31 / 9 | 333 | ✗ | 0 |

9 個 frame 同 CUI-0029 量到嗰 9 個一樣，包括 `.venv/lib/python3.11/site-packages/…` 同 `/home/user/Python-Project-Run365Days/src/api/schema.py`。

**影響**

CUI-0029 票上寫明「Log 量放大（呢個先係實際成本）：觸發成本係 998 token 一個 request、public read-only endpoint、唔使認證」。`{ activities(offset: -1) { id } }` 係 **7 個 token、33 bytes**，換到 **2016 bytes log（61× 放大）**——比票上嗰個觸發平 140 倍，而且同樣唔使認證。即係話 CUI-0029 想擋嘅放大**未消除，只係換咗個更平嘅入口**。Client 面照樣乾淨（只有一句可讀 message），問題純粹喺 server log。

**建議**

`RefusalAwareSchema` 嘅分類準則已經係「exception type 而唔係 message substring」，所以擴展好直接：

1. 抽一個共用 base（例如 `ClientRefusalError(GraphQLError)`），`BudgetExceededError` 同一個新嘅 `BoundsError` 都繼承佢；`process_errors` 改為認 base
2. `_page()` / `_track_points()` 改掟 `BoundsError(info, msg)`，帶住 resolver 嘅 `nodes` / `path`（同 `BudgetExceededError.__init__` 一樣嘅機制）
3. `_page` / `_track_points` 目前簽名唔收 `info`，要跟 `BudgetExceededError` 嗰個做法傳入
4. ⚠️ **唔好動** unseeded budget 嗰條 `RuntimeError`——佢係設定錯誤唔係 client 拒絕，必須保留 ERROR + traceback
5. ⚠️ **唔好動** `Int` coercion failure（`2.5` / `2147483648`）——佢哋喺 resolver 之前發生、本身冇 traceback（實測 introspection refusal 只有 333 bytes、零 frame），而且 `source.ts` 嗰個跨 mode 措辭表釘住咗佢哋嘅 message，改動會令 `test_a_points_the_int_scalar_cannot_carry_is_refused_before_the_resolver` 同 static-mode 文件同時錯

**驗證方式**

- 上表六行重量一次：頭四行 stderr bytes **降到 0**，最尾兩行維持原狀
- Client payload 逐欄不變（message / locations / path）—— 照 `test_a_budget_refusal_still_tells_the_client_where_it_happened` 個 pattern 加 parametrize
- `test_an_unexpected_resolver_error_is_still_logged_as_a_server_fault` 同 `test_an_unseeded_budget_still_logs_its_traceback` 維持綠
- 全 suite 綠、coverage 唔跌
