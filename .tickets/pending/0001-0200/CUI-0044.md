## 問題描述

CUI-0036 原本要求 `pages.yml` 加 **`npm audit`（前端）同 `pip-audit`（Python）** 兩樣。
User 當時明確只揀咗 `npm audit --omit=dev`，所以 lane 守住範圍只做咗前端一半 —— **呢個係啱嘅**。

但缺口要有飛：**Python 側先係真正落 Vercel production runtime 嗰半**。
Flask 同 Strawberry 係 core dependency（`CLAUDE.md` §6：Vercel 由 `pyproject.toml` 裝但唔裝
optional extras），所以佢哋直接入 production。

Reviewer 實測核實：

```
$ git grep -n "pip-audit" 6576e56 -- .github/
(零命中)
$ git grep -niE "audit|dependabot|codeql|snyk|trivy" 6576e56 -- .github/
(零命中)
```

即係話 CUI-0036 之前，`.github/` **完全冇任何依賴審計 / SCA 機制**；而家有咗前端嗰個，
Python 側仍然係零。

## 影響

中。今日唔緊急 —— CUI-0032 嗰陣 reviewer 人手行過 `pip-audit` 係**零漏洞**，
所以加落去即刻係綠，唔會 park CI 紅。但「人手行過一次」唔係 gate。

## 建議

喺 `pages.yml` 個 `lint-test` job 加 `pip-audit`。

⚠️ 執票前要重新量一次今日嘅 `pip-audit` 結果 —— CUI-0032 之後依賴已經變過
（`pytest-cov` 加咗入 `[dev]`）。如果而家非零，要同 user 確認 gate 策略，
**唔好**自己揀一個收窄嘅 threshold 就當做完（呢個正正係 W-034 嗰個「理由書寫闊咗」嘅形狀）。

## 驗證方式

- Gate 要分得開紅綠：造一個有已知 advisory 嘅依賴驗佢真係紅（喺 scratchpad 做，唔好 commit）
- 今日嘅樹要綠
- 同 `npm audit --omit=dev` 一樣，flag 旁邊要寫明**點解**係呢個 scope
