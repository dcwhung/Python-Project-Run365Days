## 問題描述

`frontend/src/views/activity/ActivityView.tsx` 對 `useTrack` 嘅**失敗狀態完全冇處理**，
結果 track query 一失敗就會落入「activity 唔存在」嗰條分支，向用戶顯示一句事實上錯嘅說話。

```
33:  const track = useTrack(current, TRACK_POINTS);
37:    () => (activity.data && track.data ? buildSeries(activity.data, track.data) : null),
69:  if (all.isPending || activity.isPending || track.isPending) return <p>Loading…</p>;
70:  if (all.isError) return <p className="text-danger">Could not load activities: {all.error.message}</p>;
71:  if (!activity.data || !series) return <p className="text-danger">Activity not found.</p>;
```

狀態機：

| `track` query 狀態 | `track.isPending` | `track.data` | `series` | 行 71 結果 |
|---|---|---|---|---|
| 成功 | false | 有 | 有 | 正常渲染 |
| 載入中 | true | — | — | 行 69「Loading…」✅ |
| **失敗** | **false** | **undefined** | **null** | **「Activity not found.」❌** |

`all.isError`（行 70）同 `activity.isError` 都有各自處理／各自路徑，**唯獨 `track.isError` 冇**。
`activity.data` 明明已經成功攞到、activity 確實存在，但用戶見到嘅係「搵唔到呢條 activity」。

## 同 AU-047 嘅關係（點解而家提出）

呢個**唔係** AU-047 引入嘅 bug —— 任何 track 請求失敗（網絡中斷、server 重啟、500）一直都會咁。
但 AU-047 為呢條路徑**新增咗一個全新嘅可達成因**：`track` budget 被拒。

- 現時前端**撞唔到** budget：全 codebase 只有一個 `useTrack` call site
  （`ActivityView.tsx:33`，`TRACK_POINTS = 600`），即每個 request 得 1 個 `track` field、
  600 點，離 `MAX_TRACK_FIELDS_PER_REQUEST = 64` 同 `MAX_TRACK_POINTS_PER_REQUEST = 10000` 好遠。
  **所以今日 AU-047 唔會令任何用戶見到呢句錯誤訊息**，本票**唔阻 AU-047 merge**。
- 但 AU-050（batch track field）一落，一個 view 攞多條 track 就會變成正常做法，
  budget 拒絕即刻成為**真實可達**嘅生產路徑。屆時錯誤訊息會由「誤導」變成「誤導兼常見」。

建議喺 AU-050 之前修好。

## 重現步驟

1. `run365-export` 之後起 API：`create_app(db_path="data/processed/run365.db")`
2. 前端以 api mode 開 `/activity/<id>`
3. 令 `TrackQuery` 失敗（任選其一，三者殊途同歸）：
   - 斷開 API（最貼近真實：網絡中斷 / server 重啟）
   - 手動將 `TRACK_POINTS` 改成 `1200`（> `MAX_TRACK_POINTS = 1000`）
   - AU-050 之後：一個 request 攞多過 64 條 track
4. 觀察畫面

## 預期結果

畫面應該講出真相並俾到出路，例如：
「Could not load the track for this activity: <message>」＋ 一個 Retry，
而 activity 本身嘅 KPI／天氣／日期等**已經攞到嘅資料照樣顯示**。

## 實際結果

畫面顯示 **「Activity not found.」** —— activity 其實存在而且 `activity.data` 已載入成功。
整頁（包括已成功攞到嘅 activity metadata）被丟棄。

**唔會白畫面**：行 71 係一個乾淨嘅 early return，React 唔會 throw，
codebase 亦冇 ErrorBoundary 需要介入。純粹係訊息錯 + 資料被無謂丟棄。

## 建議修復方向

1. 喺行 70 之後補一條 `track.isError` 分支，**訊息要講 track 而唔係 activity**：
   ```tsx
   if (track.isError) return <p className="text-danger">Could not load the track: {track.error.message}</p>;
   ```
2. 更好嘅做法：**分層降級** —— `series` 為 null 時仍然渲染 activity header／KPI／天氣，
   只喺圖表同地圖嗰格顯示 track 錯誤。已經攞到嘅嘢冇理由一齊丟。
3. 行 71 收窄成 `if (!activity.data) return <p>Activity not found.</p>;`，
   令呢句只喺真係搵唔到 activity 嗰陣出現。
4. 如果 budget 拒絕將來會係常見成因，可以認住 `extensions.code`（見 **CUI-0018**）
   俾一句可操作嘅提示（「一次過攞太多條 route，請減少數量」）而唔係原始 server 訊息。
