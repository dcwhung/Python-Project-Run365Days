# CUI-0021 api mode（Python `round`）同 static mode（JS `Math.round`）嘅 track 取樣差一個 index

**狀態**：pending
**類型**：bug（潛在，今日不可達）
**優先級**：🔵 Low
**來源**：QA Report 2026-09-15（§8）
**建立日期**：2026-09-15
**建立人**：QA Agent
**負責人**：Backend Developer
**注意**：**pre-existing，唔係今次 batch 引入**（`_even_positions()` 函數本體今次冇改）

## 問題描述

兩個 deployment mode 用兩份取樣實作：

| 位置 | rounding |
|---|---|
| `src/api/service._even_positions()` / `src/dashboard/builder.downsample()` | Python `round()` = half-to-**even** |
| `frontend/src/lib/downsample.ts` | `Math.round()` = half-**up** |

`_even_positions()` 嘅 docstring 只 claim 同 `builder.downsample` 一致（呢句啱），
但冇講同 static mode 嘅 TS 實作唔一致。

## 實測

掃過真實 export 所有 `(track_length, points)` 組合：
**45,117 個組合入面 10,189 個（22.6%）兩邊差一個 index**。
例：`len=250, points=3` → Python 取 index 124，JS 取 index 125。

## 影響

**今日零影響**：前端 `ActivityView.TRACK_POINTS = 600`，而 export `point_limit=600`
令所有已存 track <= 600，兩邊都原樣回傳（divergent = 0）。
但 `TRACK_POINTS` 一調細（或者將來加一個「低解析度預覽」），
api mode 同 static mode 就會畫出微妙唔同嘅路線。

## 建議

- 揀一邊做準（建議以 Python 為準，因為 export 本身用 Python `downsample` 寫 static JSON），
  另一邊改成同樣 rounding；
- 或者喺 `_even_positions()` docstring 明文寫低呢個 known divergence 同佢點解今日不可達；
- 加一個 cross-mode test（同一 `(len, points)` 兩邊取樣結果要一樣）。
