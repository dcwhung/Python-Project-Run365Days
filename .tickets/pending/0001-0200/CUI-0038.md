# CUI-0038 `REFUSAL_LOG_LEVEL` 改成 `WARNING` 可以殺死 CUI-0029 嘅頭號性質而 418 條測試全綠

**類型**：test-gap
**優先級**：🟡 Medium
**來源**：QA Report 2026-09-16（CUI-0029 batch，§4.1 mutant 1）
**建立日期**：2026-09-16
**建立人**：QA Agent
**負責人**：Backend Developer
**相關**：CUI-0029

**問題描述**

`REFUSAL_LOG_LEVEL` 個 docstring 講明點解要 `INFO` 而唔係 `WARNING`：「`logging`'s default threshold is `WARNING`. A deployment that configures nothing — which is the Vercel default and the condition CUI-0029 was measured under — therefore drops these records entirely, so the log-volume amplification … goes to zero rather than to one line per request.」

呢個係成張票賣嘅頭號性質。但**冇任何斷言釘住佢**。`test_a_budget_refusal_is_not_logged_as_a_server_fault` 唯一嘅 level 斷言係：

```python
assert REFUSAL_LOG_LEVEL < logging.ERROR, "a refusal logged at ERROR is the state being fixed"
```

`logging.WARNING`（30）滿足 `< logging.ERROR`（40）。

**實測（2026-09-16，in-process mutation，清 `__pycache__`，先用 oracle assert mutant 生效）**

```
oracle: logging.getLevelName(REFUSAL_LOG_LEVEL) -> WARNING     ← mutant 確認生效
Vercel 預設 config 下一個 budget refusal 嘅 stderr: 0 bytes -> 553 bytes
pytest tests -q -> 418 passed                                   ← 冇一條掛
```

**影響**

CUI-0029 量度出嚟嘅結論（Vercel 上 0 bytes）得個講字，冇 gate 守。任何人「順手把 refusal 提去 WARNING 好搵啲」都會靜靜地把票上嘅成果還原，而所有 gate 照綠。

**建議**

一行：

```python
assert REFUSAL_LOG_LEVEL < logging.WARNING, (
    "a refusal at WARNING or above is emitted by a deployment that configures "
    "nothing, which is the Vercel default CUI-0029 measured 0 bytes under"
)
```

或者更貼近性質本身：加一條測試，喺一個乾淨 logger state 下（`logging.getLogger("strawberry.execution")` 冇 handler、root 用預設 level）確認 refusal record **唔會被 emit**，而 fault record 會。

**驗證方式**

- 把 `REFUSAL_LOG_LEVEL` 改成 `logging.WARNING` → 測試**必須紅**
- 改成 `logging.ERROR` → 仍然紅（現有斷言已守住）
- 改成 `logging.DEBUG` → 綠（合法）
- 全 suite 綠
