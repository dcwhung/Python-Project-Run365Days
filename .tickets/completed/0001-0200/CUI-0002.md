## 問題描述

AU-003 將 `src/common/time.py` 由 `pytz` 換成 `zoneinfo`，正確修好咗 LMT `+07:37` 問題。
但兩者取得時區資料嘅方式完全唔同：

- `pytz` 係一個 **PyPI package，自己帶埋成套 tz database**，裝咗就一定有得用
- `zoneinfo` **唔帶資料**，佢讀 host 嘅 `/usr/share/zoneinfo`，搵唔到先 fallback 去
  `tzdata` PyPI package

而 `pyproject.toml`：

- 第 14 行仍然宣告 `"pytz"` —— 但全 repo 已經冇任何 `.py` import 佢（死依賴）
- **完全冇宣告 `tzdata`**

即係 package 而家依賴一項冇寫落 dependency list 嘅資源。

另外一個放大因素：`ZoneInfoNotFoundError` 嘅 MRO 係
`ZoneInfoNotFoundError → KeyError → LookupError → Exception`。
佢**唔係** `ValueError`，所以 `src/activities/parsers/base.py:146` 嗰句
`except ValueError` 接唔到。喺一部冇 tz database 嘅 host 上，唔係「某幾個檔案 parse 唔到」，
而係第一個檔案就令成個 `parse_all` 中止，`run365-export` 死。

## 重現步驟

```bash
# 模擬一部冇 system tz database 嘅 host（Windows、slim / distroless container）
PYTHONTZPATH="" python3 -c "
from run365days.common.time import parse_datetime
print(parse_datetime('2021-10-17 06:10:56'))
"
```

## 預期結果

要麼 `pyproject.toml` 宣告 `tzdata`（並移走已經冇人用嘅 `pytz`），
要麼明文寫低「本 package 要求 host 提供 tz database」。

同一條件下，基準 `1896778`（`pytz`）正常回 `2021-10-17 06:10:56+07:37`。

```
ZoneInfoNotFoundError MRO: ['ZoneInfoNotFoundError', 'KeyError', 'LookupError', 'Exception', 'BaseException']
caught by parse_all's `except ValueError`? False
```

- **兩個 CI 目標現時唔受影響**：`pages.yml` 行 `ubuntu-latest`，有 system tzdata（實測本機同款環境正常）
- **有風險嘅環境**：Windows 開發機、slim / distroless container、任何精簡 Python base image
- **附帶問題**：`pytz` 仍然被裝但零使用，dependency list 同真實情況唔一致

## 建議修復方向

1. `pyproject.toml` dependencies：移走 `"pytz"`，加 `"tzdata; platform_system == 'Windows'"`，
   或者為求穩陣無條件加 `"tzdata"`（純資料 package，體積細）
2. `requirements.txt` 同步
3. 考慮喺 `parse_all` 嘅 except 清單處理 `LookupError`，或者喺 `time.py` 將
   `ZoneInfoNotFoundError` 包成一個講得明「請安裝 tzdata」嘅錯誤 —— 現時個 traceback
   對唔識 zoneinfo 嘅人嚟講好難解讀
4. 補測：`PYTHONTZPATH=""` 之下斷言錯誤訊息可讀（唔係裸 `KeyError`）
