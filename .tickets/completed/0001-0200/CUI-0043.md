## 問題描述

CUI-0008 喺 `src/common/geo.py` 個 `haversine_distance` 加咗有限性 guard，非有限即掟
`ValueError`。但 reviewer 追齊三個 parser 之後發現：**唯一一條真實會出現 corrupt 座標嘅路徑
去唔到嗰個 guard。**

| Parser | lat/lon 讀法 | 非有限值會點 |
|---|---|---|
| `gpx.py:124-125` | `parse_finite_float` | 掟 `ActivityParseError` ✅ 擋得住 |
| `kml.py:160-161` | `parse_finite_float` | 掟 `ActivityParseError` ✅ 擋得住 |
| **`tcx.py:134/137`** | **`optional_float`** | **洗成 `None`** ⚠️ |

`base.py` 入面 `optional_float` 最後一行係 `return value if math.isfinite(value) else None`。
而 `None` 喺 `haversine_distance` 入面正正係「室內語意」—— 答 `nan`、靜靜哋跌出個 sum。

即係話：一個 `<LatitudeDegrees>inf</LatitudeDegrees>` 嘅 TCX **唔會**觸發 CUI-0008 個
`ValueError`，佢會行返 CUI-0008 明文話唔可接受嗰條路 ——「壞段變 nan、nan 跌出 sum、
caller 攞到少咗嘅距離」。

## 影響

低，而且**唔係 CUI-0008 整出嚟嘅**（`optional_float` 呢個行為係 W-005 嘅刻意決定）。
但 `geo.py` 個 docstring 話個 guard 係為 "corrupt input" 而設，而唯一真實會 corrupt 嘅 parser
永遠去唔到嗰度 —— 將來容易誤以為呢條路已經封咗。

## 建議

**方案 A**：TCX 嘅 lat/lon 改用 `parse_finite_float`，同 GPX / KML 睇齊。
⚠️ 要評估 W-005 當初點解揀 `optional_float` —— 如果係因為 TCX 真係有合法嘅缺值 trackpoint，
咁改動會令本來跳過嘅檔案變成掟 `ActivityParseError`。**執票前一定要用真數據量一次**
（`data/raw/` 有幾多個 TCX trackpoint 缺 lat/lon）。

**方案 B**：淨係喺 `geo.py` docstring 補一句，講明 TCX 呢條路經 `optional_float` 洗成 `None`，
所以個 guard 對佢無效。零風險，但個窿仲喺度。

**🎯 建議 B 即刻做（已喺 review 報告記錄），A 排期**，因為 A 要真數據支撐。

## 執行結果（2026-09-17，Backend Developer）

**採用方案 A**（TCX lat/lon 改用 `required_float`，即 `parse_finite_float` 之上嗰層），
`geo.py` 一個字都冇改。

### 真數據量度（365 個 `data/raw/garmin/tcx/*.tcx`，用獨立 oracle 直接掃 XML）

| 量度 | 數字 |
|---|---|
| 檔案 | 365 |
| Trackpoint 總數（全部 `Running`、全部有 `<Time>`） | 134,744 |
| **完全冇 `<Position>` element**（室內／失鎖） | **37,565（27.9%），散落 345 / 365 個檔案** |
| 有 `<Position>` 嘅 trackpoint | 97,179 |
| `<Position>` 入面缺 `LatitudeDegrees` 或 `LongitudeDegrees` | **0** |
| 讀到但 `float()` 解唔到 | **0** |
| 讀到但非有限（`inf` / `nan`） | **0** |

結論：TCX 合法嘅「缺座標」**全部**發生喺 `<Position>` 唔存在呢一層，而嗰層由
`tcx.py` 自己嗰句 `if pos is not None else None` 擋住，**根本唔經 `optional_float`**。
一旦 `<Position>` 在場，兩個 degrees 喺真數據入面 100% 齊全、可解析、有限。
所以改用 `required_float` 喺真數據上**refuse 唔到任何一個現有 trackpoint**。

A/B 實證（同一 process，`setattr` 裝返 pre-CUI-0043 個 body，並 assert 佢真係行過 2,592 次）：
兩邊 365/365 檔案、134,744 個 trackpoint 嘅 `(lat, lon)` + `distance_by_coord_km` +
`distance_km` digest **完全相同** → 零行為回歸。

### W-005 原本點解揀 `optional_float`

查 `.proj-docs/reviews/2026-09-13_review_p0-batch.md` W-005 全節：W-005 **由頭到尾冇考慮過座標**。
佢處理嘅係 `optional_int("nan")` raise `ValueError`、`optional_int("inf")` raise `OverflowError`
衝穿 `parse_all` 拉冧整個 export；`isfinite` guard 落喺 `optional_float` 嘅理由白紙黑字係
「nan 污染 sum、inf 污染 min/max」—— 即 cadence / speed / altitude / calories 呢類**統計**欄位。
座標用 `optional_float` 係 W-005 之前就有，原因係 `<Position>` 本身 optional，
唔係「合法缺值 lat/lon」。**W-005 冇任何明文理由阻止方案 A**，票上「W-005 定案」嘅講法唔成立。
