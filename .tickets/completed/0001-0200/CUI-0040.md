# CUI-0040 `service.tracks()` 收到負數 `points` 靜靜回 1 行，同 CUI-0033(a) 立嘅原則相反

**狀態**：✅ done
**類型**：tech-debt / robustness
**優先級**：🟢 Low
**來源**：QA Report 2026-09-16（CUI-0029 batch，§4 edge case E2）
**建立日期**：2026-09-16
**建立人**：QA Agent
**負責人**：Backend Developer
**相關**：CUI-0033（本票係佢個原則嘅延伸）
**注意**：**兩個 shipped client 都到唔到**——`schema._track_points` 同 `static/source.ts` 嘅 `checkPoints` 都會先擋

**問題描述**

CUI-0033 (a) 嘅論證係：「`MAX_TRACK_POINTS` 唔可以淨係 bound 個問題，要 bound 埋個答案」——即 service 層唔應該假設 caller 幫佢守住。但同一個 function 對負數 `points` 仍然完全信 caller。

**實測（2026-09-16，真 `run365.db` + 一條 1250 行 synthetic track，只 flush 唔 commit）**

| `points` | `len(tracks(s, ["QA-EDGE"], points)["QA-EDGE"])` |
|---|---|
| `None` | 1000 ← 上限，正確 |
| `0` | 1000 ← falsy → 上限，正確 |
| `False` | 1000 ← 正確 |
| **`-5`** | **1** ← ⚠️ 靜靜回 1 行，唔 raise 唔 clamp |
| `1` | 1 |
| `1000` | 1000 |
| `1001` | 1000 ← `min()` cap，正確 |
| `10**9` | 1000 ← 正確 |

未知 id 一律回 `{'nope': []}`，三個值都一致 ✅。

`min(points, MAX_TRACK_POINTS)` 對 `-5` 回 `-5`，再交去 `_even_positions(1250, -5)`，結果係 1 行——同 `points=1` 撞埋一齊，client 分唔出「我問咗負數」同「我問咗 1」。

**影響**

低。兩個 shipped client 都守住咗，所以今日到唔到。但：
1. `tracks()` 個 docstring 寫「`points`: Samples per track, or `None`/`0` for every stored row up to `MAX_TRACK_POINTS`」——完全冇講負數
2. CUI-0033 (a) 嘅整個理由就係「唔好靠 caller 守」，呢度係同一類遺留
3. 將來任何新 caller（另一個 CLI、另一個 mode、一條 script）都會踩

**建議**

`tracks()` 開頭 clamp 或 raise。Clamp 較簡單同 `min()` 一致：

```python
sample = min(points, MAX_TRACK_POINTS) if points and points > 0 else MAX_TRACK_POINTS
```

⚠️ 但咁樣 `-5` 就變成 1000（「當冇講」），同 `points=0` 一樣。另一個選擇係 raise `ValueError`，同 `_track_points` 措辭一致。**由 developer 揀，但要喺 docstring 講明揀咗邊個**，因為 `0` 同 `-5` 兩個 falsy/negative 嘅語意分別就係 CUI-0025 當初拗過嗰樣嘢。

**驗證方式**

- 對住一條 > 1000 行嘅 synthetic track 逐個值重量上表，`-5` 行為變成揀定嗰個
- `_even_positions` 相關測試維持綠
- 兩個 client 嘅行為零改動（`schema._track_points` / `checkPoints` 仍然先擋，所以 GraphQL 同 static 兩邊嘅 message 唔可以變）
- 全 suite 綠
