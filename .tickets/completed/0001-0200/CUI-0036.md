## 問題描述

Reviewer 喺 CUI-0032 嘅 security gate 行咗 `pip-audit`（Python 側，零漏洞）。
**但冇任何一輪 review / QA / CI 行過 `npm audit`。**
QA 今次行咗，結果：

```
14 vulnerabilities (2 moderate, 12 high)
```

## 明細

| Severity | 入口 package | 根源 |
|---|---|---|
| high × 11 | `@graphql-codegen/*`（`cli`, `client-preset`, `add`, `core`, `plugin-helpers`, `schema-ast`, `typescript`, `typescript-operations`, `typed-document-node`, `gql-tag-operations`, `visitor-plugin-common`）| `lodash` —— *Code Injection via `_.template`* |
| high × 1 | `lodash` | 同上（直接） |
| moderate × 2 | `vitest`, `@vitest/mocker` | *Path Traversal / Arbitrary File Read via `@vitest/mocker` Redirect Mock* |

## 暴露面核實（QA 實測）

**全部 14 個都只經 `devDependencies` 到達，冇一個入到 browser bundle。**

`frontend/package.json` 嘅 `dependencies` 得八個，一個都唔喺上面張表：

```
@tanstack/react-query, chart.js, graphql, graphql-request,
react, react-chartjs-2, react-dom, react-router-dom
```

而 `frontend/src/` 入面 `grep -rn "graphql-codegen\|lodash"`（排除 `*.test.*`）**零命中**。

所以：

- **零 runtime / 零 browser 暴露** —— 呢個係本票唔係 🔴 嘅唯一理由
- 暴露面係 **build-time 同 CI**：`npm run codegen`（`npm run typecheck` / `npm test` / `npm run build`
  三個 script 都會先行佢）同 `vitest run`，兩者都喺 CI runner 上行
- 兩個漏洞都要攻擊者控制輸入（`_.template` 要 attacker-controlled template key；
  `@vitest/mocker` 要 attacker-controlled test）。呢個 repo 係 public，
  所以「PR 入面帶一個惡意 test / 惡意 GraphQL document」唔係純理論

## 影響範圍

- **零依賴改動**：`git diff --stat 6cb7529..HEAD -- pyproject.toml frontend/package.json frontend/package-lock.json` 為空。
  **唔係本 batch 引入**，所以**唔阻 CUI-0025 / CUI-0028 / CUI-0032 結案。**
- 真正嘅問題係 **process gap**：`pip-audit` 有人記得行（而且係人手、喺 scratch venv 行），
  `npm audit` 冇人行過，兩者都唔喺 `.github/workflows/pages.yml`。
  今日呢個 14 係「碰啱有人行咗一次」先見到。

## 建議修復方向（由 devops 判斷）

1. **先補 gate，再補 bump**（推薦次序）。`npm audit` 一日唔喺 CI，
   今次 bump 完下次一樣會靜靜哋累積返。
   - `pages.yml` 加 `npm audit --audit-level=high`（前端）同 `pip-audit`（Python）
   - ⚠️ 直接加會**即刻令 CI 紅**（今日就已經有 12 high）。
     所以要同 (2) 一齊上，或者第一步用 `--audit-level=critical` 再收緊。
2. **Bump**：`@graphql-codegen/cli` + `@graphql-codegen/client-preset` 同 `vitest` 升到冇 advisory 嘅版本。
   ⚠️ `vitest` 係 major 風險位（今日 3.2.7，131 條測試 / 22 個檔案全部靠佢）；
   codegen 升級要重跑 `npm run codegen` 同 `run365-schema --check` 確認 SDL / 產出物冇 drift。
   ⚠️ **唔好**用 `npm audit fix --force`（會 downgrade / major bump 到冇人審過嘅版本）。
3. **記錄**：`docs/deployment.md` 寫低兩個 audit 係 CI 嘅一部分同埋 threshold 係乜。
