## 問題描述

`S-011` 記低咗兩個殘留問題，Main agent 2026-09-16 核實**兩個今日都仍然成立**。

### (a) `points: 0` 兩個 mode 行為相反

| Mode | 代碼 | `points = 0` 嘅結果 |
|---|---|---|
| **api** | `src/api/schema.py` `_track_points()`：`if not 1 <= points <= MAX_TRACK_POINTS: raise ValueError` | **拒絕** —— `points must be between 1 and 1000, got 0` |
| **static** | `frontend/src/data/static/source.ts:66`：`return points ? downsample(rows, points) : rows;` | **回全部點**（`0` 係 falsy，短路咗） |

同一句 `useTrack(id, 0)`，api mode 出錯誤、static mode 回成條 track。

⚠️ 留意 `points` 喺 static source 嘅 signature 係 `points?: number`（optional），所以 `undefined` 同樣會行「回全部」呢條路；
而 api 側 SDL 係 `track(points: Int! = 150)`（NonNull + default），根本冇 `undefined` 呢個狀態。

**點解「回全部」係錯嘅一邊**：`S-011` 已經裁決過 —— AU-001 之前 api mode 都係 `if points:`，
即 `points = 0` 等於「無上限」，正正就係 AU-001 要堵嘅 DoS 向量。所以拒絕 0 唔止安全，
仲修正咗一個反直覺嘅語義。**唔好將 api mode 改返去遷就 static mode。**

### (b) `points` / `limit` 嘅範圍冇寫入 SDL

`MAX_TRACK_POINTS = 1000`（`schema.py:31`）同 `MAX_PAGE_SIZE = 1000`（`schema.py:223`）
兩個界**只存在於 Python docstring 同 runtime 錯誤訊息**。

核實 `frontend/schema.graphql` 現況（2026-09-16，CUI-0004 之後）：

- `track(points: Int! = 150)` 個 description **已經有**：`points: 1` 語義、64 個 field 上限、10000 點總額
  （AU-047 / CUI-0004 陸續補咗）
- 但**仍然冇** `points` 本身嘅 1–1000 範圍
- `activities(… limit: Int! = 500, offset: Int! = 0)` 亦**冇** `MAX_PAGE_SIZE` 呢個界；
  `weight` / `weather` / `warnings` 三個 field 同樣

前端開發者睇 `frontend/schema.graphql` 同 generated type，見唔到自己會撞邊度。

## 可達性

**今日零影響**，兩半都係。已核實冇任何 caller 送 0 或者省略 `points`：

- `frontend/src/views/activity/ActivityView.tsx` → `TRACK_POINTS = 600`
- `frontend/src/data/api/source.ts` → `DEFAULT_TRACK_POINTS = 600`，`track(id, points = DEFAULT_TRACK_POINTS)`
- generated `TrackDocument` → `$points: Int!`（NonNull，必傳）

風險喺於：任何人第一次寫 `useTrack(id, someValue)` 而 `someValue` 計出嚟係 `0`，
兩個 deployment mode 會做兩件完全唔同嘅事，而**冇任何測試會 fail**。

## ⚠️ CUI-0021 之後多咗第三種可能行為（執票時要留意）

CUI-0021 令 `frontend/src/lib/downsample.ts` 同 Python 對齊，其中包括 `limit < 2` 回最後一點。
所以如果只係簡單將個 guard 由 `points ?` 改成 `points != null`，`points: 0` 會變成
**「回最後一點」**而唔係「回全部」—— 即係話而家有三種可能結果，唔可以求其揀：

| 做法 | `points = 0` 結果 |
|---|---|
| 現狀 `points ? … : rows` | 回全部點 |
| 改成 `points != null ? downsample(…) : rows` | 回最後一點（`downsample` 嘅 `limit < 2` 分支）|
| 明確拋錯（同 api mode 一致） | 拒絕 |

## 建議方向

### (a) 建議：static source 明確拋錯，同 api mode 對齊

```ts
async track(id: string, points?: number): Promise<TrackPoint[]> {
  // 需要決定 undefined 點算：保持「回全部」定係都拋錯？
  ...
}
```

要順帶決定嘅事：
1. `undefined`（即 caller 冇傳）應唔應該仍然係「回全部」？static mode 冇 server 保護，
   「回全部」對一個 600 點嘅 track 其實冇害；但咁樣 `undefined` 同 `0` 就有唔同語義，要寫清楚
2. 錯誤形態要唔要同 api mode 一樣（`points must be between 1 and 1000, got 0`）？
   兩個 mode 嘅 error 形狀一致，client 嘅 error handling 先寫得一份
3. `MAX_TRACK_POINTS = 1000` 呢個上界 static mode 要唔要都守？（今日 static track ≤ 600，實際唔會撞）

### (b) 建議：範圍寫入 SDL description

喺 `schema.py` 嘅 field description 補上範圍，例如
`"…evenly downsampled to `points` samples (1–1000)."`、`limit` 補 `(1–1000)`。
呢啲會自動流入 `frontend/schema.graphql` 同 generated types 嘅註釋。

⚠️ 改 SDL description 之後必須跑 `run365-schema --check frontend/schema.graphql`，
唔同步就要更新個 `.graphql` 檔案（CI 有呢個 gate）。

同 `S-012` 定落嘅 pattern 一致：常數值嵌入 SDL description，由 `run365-schema --check` 守住同步。

## 執行決定（Backend Developer，2026-09-16）

「建議方向」留低嘅四個決定，逐個揀咗同埋點解：

| # | 決定 | 理由 |
|---|---|---|
| 1 | `points: 0` **拋錯**，同 api mode 一致 | 票上三選一入面，「回全部」正正係 AU-001 堵咗嘅 DoS 讀法，「回最後一點」係 CUI-0021 意外造成嘅第三種行為、冇人要求過。淨低拒絕一條。 |
| 2 | `undefined` **維持「回全部」** | api mode 根本冇呢個狀態可以唔一致：佢個 SDL argument 係 `points: Int! = 150`，NonNull 加 default。而 export 本身封頂 600 行一條 track，所以「全部」係由結構封住而唔係由 caller 封住。另外咁樣 CUI-0025 對現有 caller 唔係 breaking change。**關鍵**：實現要用 `points === undefined` 而唔係 falsy 判斷，`0` 先會跌落 guard。 |
| 3 | 錯誤形態 **逐字一樣**：`points must be between 1 and 1000, got 0` | 兩個 mode 出同一句，client 嘅 error handling 寫一份就夠。兩邊測試都 assert 成句而唔係 assert 個數字。 |
| 4 | 上界 `MAX_TRACK_POINTS = 1000` **static mode 都守** | 今日撞唔到（static track ≤ 600），但守住先可以講「兩個 mode 契約一樣」，SDL 寫低嘅 `(1-1000)` 先對兩邊都成立。 |

額外第五個決定（票上冇問，但同屬「`points` 契約」）：**非整數一併拒絕**。
api mode 表達唔到（SDL 係 `Int!`），而 `downsample` 自己個 docstring 明寫非整數 `limit` 喺佢 claim 之外
（Python `range(2.5)` 掟錯，TS 側會靜靜哋回 2 件）。唔 guard 就係留返個靜默錯誤。

(b) 範圍寫入 SDL：`points` 同 `limit` 兩個範圍都寫成 `(1-1000)`。
`MAX_PAGE_SIZE` 揀咗放喺新嘅 `PAGE_WINDOW_NOTE` 而唔係 `LIST_ROWS_NOTE`，
因為 `year` 使緊 row budget 但冇 `limit` argument —— 即 S-053 嗰項，同一個 commit 之後跟手做。
