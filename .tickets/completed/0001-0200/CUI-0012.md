## 問題描述

三處無防護嘅 BeautifulSoup `.find()`，同 AU-002 修好嗰批 parser 係同一類問題
（`.find(...).text` 鏈遇到缺失元素就 `AttributeError`）：

### 1. `src/weather/collectors/hourly.py:57`（硬崩）

```python
script = str(tds[9].find("script").string)
```
一行冇 `<script>` 就 `AttributeError`，**成日嘅數據死晒**。
已有 fixture 同測試等緊：`tests/fixtures/weather/freemeteo_no_script.html`
＋ `test_a_row_without_a_weather_script_still_crashes`（測試釘住現行崩潰行為，修好時要一併更新）。

### 2. `src/weather/collectors/warnings.py:55`（**靜默錯，最陰險**）

```python
html.find(marker)   # 搵唔到返 -1
... -1 + len(marker) == 31
```
marker 唔存在時，`find()` 返 `-1`，加 `len(marker)` 之後變成 `31` ——
即係**由整頁嘅第 31 個字元開始 parse**，而唔係「乜都唔 parse」。

後果：HKO 一旦改個標題，collector 唔會失敗，而係去 scrape 一批**唔相干嘅 6-cell table**，
靜靜咁攞返錯資料。呢個比崩潰差 —— 崩潰至少睇得見。

### 3. `src/weather/collectors/warnings.py:70`（硬崩）

```python
tds[0].find("img").get("src", "")
```
同 #1 同一個 pattern。

## 建議修復方向

三處統一處理。可以參考 AU-002 喺 `src/activities/parsers/base.py` 建立嘅做法
（`element_text()` / `required_text()` / guarded read helper），但**唔好照抄** ——
BeautifulSoup 同 `xml.etree` API 唔同。

`warnings.py:55` 嗰個 `-1` 要明確處理：搵唔到 marker 應該係**明確錯誤或明確空結果**，
唔可以靜靜咁 fallback 去一個岩岩巧合可以 parse 嘅 offset。

三個 collector 而家有 100% 測試覆蓋（CUI-0010），所以改動有網接住。

### 票上講法嘅更正（實測）

1. **行號全部漂移咗**：實際係 `hourly.py:67`（票寫 57）、`warnings.py:56`（票寫 55）、
   `warnings.py:73`（票寫 70）。
2. **`31` 嘅算術啱，但描述差一個位**：`len(marker)` 量到係 **32**，`-1 + 32 == 31` 正確；
   但 `html[31:]` 係由**索引** 31 開始，即係整頁嘅**第 32 個**字元（1-based），唔係「第 31 個」。
3. **原有 fixture 證明唔到呢個缺陷**：喺 `hko_warning_day.html` 上面移走 marker，錯位 parse
   **一樣返 3 條正確記錄** —— 因為 offset 31 斬斷咗第一個 `<table>` 嘅開 tag，
   `find_all("table")` 搵唔到嗰個孤兒 `<tr>`。所以新開咗 `hko_warning_day_no_marker.html`：
   marker 唔存在，而 offset 31 之後有一個**完整**嘅六格表，修復前返 1 條
   `ROW FROM AN UNRELATED TABLE`（靜默錯），修復後掟 error。
4. **「現有 247 條測試全綠」過時**：base `6576e56` 實際係 **418 passed**。
5. **點解揀「掟 error」而唔係「返空 list」**：`hko_warning_day_empty.html` 證明咗
   marker 係 page furniture —— 一日冇任何警告，個 heading 一樣喺度。
   所以 marker 唔見 = 版面改咗，同「今日冇警告」係兩件事。
