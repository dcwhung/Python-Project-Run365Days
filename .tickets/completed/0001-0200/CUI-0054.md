# CUI-0054 每日 `npm audit` 由 2026-09-30 起連續紅：一條修到，一條上游冇得修

**狀態**：✅ done（2026-10-05）—— 用有期限嘅 allowlist，見「決定」一節
**類型**：ci / supply-chain
**優先級**：🟡 Medium
**來源**：Project status 檢查 2026-10-05（`audit.yml` 嘅 scheduled run）
**建立日期**：2026-10-05
**建立人**：Main agent
**負責人**：DevOps Engineer
**相關**：CUI-0036（npm audit 入 CI）、CUI-0049（全樹零 advisory）、CUI-0052（audit 搬出部署路徑）、W-034 / S-095（allowlist 漂移嘅先例）

---

## 問題描述

`.github/workflows/audit.yml` 嘅 `Audit npm dependencies` job 由 2026-09-30 開始，每日 scheduled run
都係紅（`Audit Python dependencies` 照綠）。`npm audit` 報咗兩個來源：

| Package | Advisory | 修到？ | 路徑 |
|---|---|---|---|
| `brace-expansion` | GHSA-q2hr-2g5m-vwhr、GHSA-qhr7-859c-m2p7、GHSA-6j4f-fj2g-mc7p | ✅ `npm audit fix`（全部係 patch bump） | `eslint` / `typescript-eslint` / `graphql-config` → `minimatch` |
| `braces` | GHSA-vfj7-8cjw-p6xm（high，CWE-674） | ❌ 受影響範圍 `<=3.0.3`，而 3.0.3 係 registry 上面最新版 | `@graphql-codegen/cli` → `micromatch` → `braces` |

`npm audit fix --force` 對 `braces` 開嘅「修正」係將 `@graphql-codegen/cli` 由 7 **降級**去 3.2.0 ——
即係推翻 CUI-0049，唔係修正。

## 影響

- Gate 係紅，但冇 job `needs` 佢（CUI-0052），所以部署冇受阻。
- 真正嘅代價係**訊號被淹沒**：一個長期紅嘅 gate，會令之後出現嘅真 advisory 冇人睇到。
- `braces` 喺本 repo 嘅實際暴露面：淨係 `graphql-codegen` 喺 build time 用嚟 match
  `frontend/codegen.ts` 入面寫死嘅路徑（`schema.graphql`、`src/data/api/queries.ts`），
  唔收外部輸入，亦唔入 production bundle。

## 決定

`audit.yml` 原本嘅註解寫明：「上游冇 fix 嘅 advisory 嚟到，答案係開 ticket 再做決定，
唔係順手加 `--audit-level` 或者 exclusion」。所以列咗四個選項，**由用戶揀**：

| 方案 | 結果 |
|---|---|
| **A. 有期限嘅 allowlist** | ✅ **揀咗** |
| B. `overrides` 指去 fork / patch | ❌ 要信任同維護一個非官方版本，而且 npm 睇版本號，照報 |
| C. 暫時接受紅，等上游 | ❌ 會淹沒之後嘅真 advisory |
| D. `--audit-level=critical` | ❌ 會連將來所有 high advisory 一齊放過，違反 CUI-0049 |

## 落地

| 檔案 | 作用 |
|---|---|
| `frontend/package-lock.json` | `npm audit fix`（冇 `--force`）：`brace-expansion` 1.1.18 → 1.1.21、5.0.9 → 5.0.12；`@graphql-codegen/cli` 7.4.1 → 7.4.3 同 `@graphql-tools/*` loader 跟住出 patch。`package.json` 冇郁 |
| `scripts/npm_audit_gate.py` | Stdlib only。讀 `npm audit --json`，對住 allowlist 判斷 |
| `frontend/npm-audit-allowlist.json` | 一條 entry：GHSA-vfj7-8cjw-p6xm / `braces` |
| `.github/workflows/audit.yml` | npm step 改成「`npm audit --json` 出報告 → gate 判斷」 |
| `tests/test_npm_audit_gate.py` | 每條規則都有測試，另外加 CLI 嘅 exit code，同埋檢查 committed allowlist 格式啱唔啱 |

一條 allowlist entry 要**同時**滿足以下全部條件先算過：

1. 未過 `expires`，而且 `expires` 唔可以超過今日加 `MAX_ALLOWLIST_DAYS`（唔可以一次過放幾年）
2. npm 仲有報呢個 advisory（修咗之後一定要刪 entry，否則紅）
3. npm 冇提供 non-breaking 嘅 fix（`fixAvailable is True` 就紅；要 major 改動嘅「fix」唔計）
4. Advisory 喺 entry 寫嘅嗰個 package 度
5. 因為佢而被 flag 嘅 package 集合**完全等於** `dependents`：多咗一條新路徑會紅，少咗一條都會紅

第 5 條係 exclusion flag 做唔到嘅。容許呢條 advisory 嘅理據係「淨係經 codegen 入嚟」；
一旦有新路徑，呢個理據就未經證實，所以要紅。

## 偵測力實測

喺本 ticket 嘅 branch，用真實嘅 `npm audit --json` 輸出（同埋喺佢上面做嘅改動）做輸入，
每個 case 都用一個獨立 subprocess 行 `scripts/npm_audit_gate.py`，睇 exit code：

| Case | 期望 | 實測 |
|---|---|---|
| 真報告，`audit fix` 之後 | 0 | **0**（附一條 `::warning`） |
| 真報告，`audit fix` 之前（`brace-expansion` 仲喺度） | 1 | **1** |
| `--today 2027-01-03`（到期嗰日） | 0 | **0** |
| `--today 2027-01-04`（過咗期） | 1 | **1** |
| 加一個經 `micromatch` 到 `braces` 嘅新 package | 1 | **1** |
| 拎走 `globby` 嗰條路徑 | 1 | **1** |
| `braces.fixAvailable = true` | 1 | **1** |
| 全樹乾淨（entry 變 stale） | 1 | **1** |
| npm 連唔到 registry 嘅 error document | 2 | **2** |
| 空檔案（npm crash） | 2 | **2** |

前端 check（`lint` / `typecheck` 連 codegen / `vitest` / `build` / `build:static`）喺 lockfile 改完之後全部綠，
`src/gql/` 產出冇變。

## 已知限制

- `schedule:` 只會行 default branch（`master`）上面嗰份 `audit.yml`。所以喺呢個改動 release
  merge 入 `master` 之前，每日 run 仲係行舊 step（淨係 `npm audit`），會繼續紅。
  `push` / `pull_request` 去 `develop` 冇呢個限制。
- 到期日係 `2027-01-03`。到時如果上游仍然未出 fix，就要開新 ticket 續期，唔可以淨係改個日期。
