## 問題描述

`src/api/schema.py` 嘅 `MAX_TRACK_FIELDS_PER_REQUEST` docstring 引嘅 wall clock 係喺
`tests/test_api.py` 嘅 `year_db` fixture 上量嘅 —— 365 activities 但**全 DB 得 600 條
track row**。真實 export 有 **134,041 條**（224 倍）。

S-033 已經令啲數字誠實地引到一個有效數字，docstring 亦有寫明 fixture 幾大。
問題係 **AU-050 新加嘅 batch 路徑**係唯一一條成本同 track row 總數有關嘅路徑，
所以只有佢喺 fixture 同 production 之間差一個數量級——而 prose 就係用呢啲數
去推論 "still some 60x inside the 15 s Vercel function"。

## 建議

1. `year_db` fixture 加一個 production 規模嘅變體（或者喺 docstring 明文並排列出
   fixture 同 production 兩組數），令 batch 路徑嘅成本睇得見。
2. 「60x inside the 15 s Vercel function」按 production 數字重述。
3. 「64 aliased track under one parent ... 同樣 ~0.01 s」實測 20.8 ms，
   一個有效數字應該係 0.02 s。

## 解決方案

只改 `src/api/schema.py` 入面 `MAX_TRACK_FIELDS_PER_REQUEST` 個 docstring，**docs-only，零代碼改動**，
所以冇 failing test 可寫（見 commit message）。測試數目維持 351 綠。

**建議 1（fixture / production 並排）** —— 選咗票上嘅「或者」分支：唔加 production 規模 fixture，
而係喺 docstring 逐個 shape 明文並排列出兩組數。理由：加一個 134,041 row 嘅 fixture 會令
整個 suite 由 ~21 s 變幾分鐘，而呢啲數全部**唔 assert**，買唔到任何 gate。

| Shape | 改後 docstring | 出處 |
|---|---|---|
| `activities(limit:64){track(points:1)}` | `~0.01 s` fixture / `~0.2 s` export（10.4 / 165.6 ms） | QA 2026-09-15 |
| `activities(limit:65)`（被拒） | `~0.01 s` fixture，**明寫 export 未量** | QA 2026-09-15 |
| 64 aliased track under one parent | **`~0.02 s`**（原本隱含 `~0.01 s`）（20.8 / 21.7 ms） | QA 2026-09-15 |
| 52 parents，同一 activity | `~0.07 s` fixture / `~0.08 s` export（68.7 / 78.2 ms） | QA 2026-09-15 |
| 52 parents，唔同 activity | `~0.1 s` fixture / `~0.2 s` export（141.4 / 194.8 ms） | QA 2026-09-15 |
| 166 aliased `activities`（無 track） | `~2 s` fixture，**明寫 QA 未喺 production 規模量過** | fixture 實測 |

**建議 3（0.02 s）** 已改：原文 "Aliasing 64 track fields … reaches the same 4 for 714 tokens"
隱含同上一句一樣係 `~0.01 s`，實測 20.8 ms，改成明文 `~0.02 s at either scale`，
並解釋點解兩個規模一樣（呢個 batch 只讀一個 activity 嘅 track，掃嘅係嗰條 track 嘅 row，唔係 export 總數）。

**建議 2（Vercel 餘裕）**：刪走 "still some 60x inside the 15 s Vercel function at the slowest
reading of this fixture" —— 呢個數喺兩個規模都對唔上（15 s / 0.2 s = 75x，15 s / 0.1414 s = 106x），
係 AU-050 之前嘅遺留。改成直接由 export 讀：390 ms → **38x**，並講明餘裕係喺 export 量、
唔係由任何 fixture 數推論出嚟。

前言段亦重寫：由「fixture 數唔 carry 去 production」收窄成
「**寬 batch** 嘅 fixture 讀數唔 carry，其餘大致 carry」——呢個先係實測講嘅嘢
（只有 64-track page 嗰條差 16x，兩條 52-parent shape 差唔到 1.4x）。
