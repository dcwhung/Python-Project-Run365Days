## 問題描述

`pyproject.toml` 嘅 `[project.optional-dependencies] dev` 得三項：

```toml
dev = [
    "pytest>=7",
    "ruff>=0.5",
    "pre-commit>=3",
]
```

**冇 `pytest-cov`**。但 coverage 係本項目一個經常引用嘅訊號 ——
`.proj-docs/qa/` 同 `.proj-docs/reviews/` 入面幾乎每份報告都引 coverage 數字，
多張 ticket（CUI-0022 / CUI-0023）嘅驗證方式亦寫明要量 coverage。

後果：每個要量 coverage 嘅 agent / 開發者都要自己 `pip install pytest-cov`，
而 `.venv` 係 gitignored，所以**每個新 clone、每個新 worktree 都要重做一次**。
本 session 至少有兩條 lane 各自撞過一次。

## 核實

```
$ sed -n '/\[project.optional-dependencies\]/,/^\[/p' pyproject.toml
dev = ["pytest>=7", "ruff>=0.5", "pre-commit>=3"]     # 冇 pytest-cov
```

## 建議修復方向

`dev` extra 加 `pytest-cov>=5`。

⚠️ **安全性核實（CLAUDE.md §6）**：CLAUDE.md 明確記低「Vercel 由 `pyproject.toml` 裝但
**唔裝 optional extras**」，所以加入 `dev` extra **唔會**令 Vercel 嘅 serverless function
多裝一個 package。呢點執票時要再核實一次（睇 `vercel.json` / `scripts/vercel-build.sh`
實際點裝），唔好照抄本票。

順帶考慮（執票者判斷）：
- 要唔要喺 `pyproject.toml` 加一段 `[tool.coverage.run]` 設定（例如 `source = ["src"]`、
  `omit` 掉 `src/cli/*`），令 `pytest --cov` 唔使每次都傳一堆 flag
- CI（`.github/workflows/pages.yml`）要唔要加一步量 coverage —— **傾向唔加**：
  coverage 門檻會變成另一個會 drift 嘅寫死數字（見 CUI-0024 / CUI-0031 嘅教訓）

## 驗證方式

- 新 clone / 新 worktree 跑 `pip install -e ".[dev]"` 之後，`pytest --cov=src` 直接行到
- `npm audit` / `pip-audit` 對新依賴冇 High 以上（全局規範要求）
- License 唔係 GPL（`pytest-cov` 係 MIT）
- 382 條測試全綠

## 執行備註（Lane E，2026-09-16）

### Vercel 前提：已核實，結論同票上一致

票上要求唔好照抄 CLAUDE.md，要自己睇檔案。睇咗兩條獨立路徑，兩條都唔會裝 extras：

1. **Serverless function 嘅 runtime 依賴** —— `requirements.txt` 得一行 `.`（淨係一點，冇 `[dev]`）。
   Vercel Python runtime 就係讀呢個檔案裝 `api/graphql.py` 個 function，
   所以只會攞到 `[project].dependencies`。
2. **Build step** —— `scripts/vercel-build.sh` 兩條分支都係 `uv pip install --quiet "."` /
   `pip install ... "."`，同樣係 bare `.`。而且個 build venv 係整喺
   `${TMPDIR:-/tmp}/run365-build-venv`，喺 checkout 之外，本身就唔會被 bundle。

補充一層：`vercel.json` 嘅 `excludeFiles` 已經剔走 `tests/`、`scripts/`、`.venv-build/`。
即係話加 `pytest-cov` 落 `dev` extra，Vercel function **零影響**。

### 安全 / License

- `pip-audit`：`pytest-cov` 7.1.0、`coverage` 7.16.1、`pluggy` 1.6.0 **零已知漏洞**。
  （同一次 audit 報咗 `pip` 24.0 同 `setuptools` 79.0.1 有 finding，但嗰兩個係 venv 自帶嘅
  bootstrap 工具，本票之前已經存在，同新依賴無關。）
- License：`pytest-cov` MIT、`pluggy` MIT、新增嘅傳遞依賴 `coverage` 係 **Apache-2.0**。冇 GPL。

### 兩個「順帶考慮」嘅決定

- **`[tool.coverage.run]`：加咗，但只加 `source = ["src"]`。** 咁樣 bare `pytest --cov` 同
  `pytest --cov=src` 會量同一個分母（實測兩者都係 1630 statements），唔會出現兩個 agent
  各自量到唔同 denominator。**刻意冇加** `omit`、`branch`、`fail_under`：
  `omit` 同 `branch` 會令 `.proj-docs/` 入面已經記低嘅 coverage 數字同新量嘅對唔上。
- **CI coverage gate：冇加**，同票上傾向一致。理由就係票自己講嗰個 ——
  門檻係另一個會 drift 嘅寫死數字（CUI-0024 / CUI-0031 嘅教訓）。
  `.github/workflows/pages.yml` 本票完全冇改。

### 驗證

喺一個全新 venv（`python -m venv` → `pip install -e ".[dev]"`，冇另外裝任何嘢）跑
`pytest tests -q --cov=src`：直接行得，390 passed，TOTAL 95%。
