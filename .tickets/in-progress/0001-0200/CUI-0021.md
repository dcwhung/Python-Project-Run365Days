# CUI-0021 api mode（Python `round`）同 static mode（JS `Math.round`）嘅 track 取樣差一個 index

**狀態**：in-progress
**類型**：bug（潛在，今日不可達）
**優先級**：🔵 Low
**來源**：QA Report 2026-09-15（§8）
**建立日期**：2026-09-15
**建立人**：QA Agent
**負責人**：Backend Developer
**注意**：**pre-existing，唔係今次 batch 引入**（`_even_positions()` 函數本體今次冇改）

## 問題描述

兩個 deployment mode 用兩份取樣實作：

| 位置 | rounding |
|---|---|
| `src/api/service._even_positions()` / `src/dashboard/builder.downsample()` | Python `round()` = half-to-**even** |
| `frontend/src/lib/downsample.ts` | `Math.round()` = half-**up** |

`_even_positions()` 嘅 docstring 只 claim 同 `builder.downsample` 一致（呢句啱），
但冇講同 static mode 嘅 TS 實作唔一致。

## 實測

掃過真實 export 所有 `(track_length, points)` 組合：
**45,117 個組合入面 10,189 個（22.6%）兩邊差一個 index**。
例：`len=250, points=3` → Python 取 index 124，JS 取 index 125。

## 影響

**今日零影響**：前端 `ActivityView.TRACK_POINTS = 600`，而 export `point_limit=600`
令所有已存 track <= 600，兩邊都原樣回傳（divergent = 0）。
但 `TRACK_POINTS` 一調細（或者將來加一個「低解析度預覽」），
api mode 同 static mode 就會畫出微妙唔同嘅路線。

## 建議

- 揀一邊做準（建議以 Python 為準，因為 export 本身用 Python `downsample` 寫 static JSON），
  另一邊改成同樣 rounding；
- 或者喺 `_even_positions()` docstring 明文寫低呢個 known divergence 同佢點解今日不可達；
- 加一個 cross-mode test（同一 `(len, points)` 兩邊取樣結果要一樣）。

## 解決方案（2026-09-16，Backend Developer）

**採納方向：以 Python 為準。** 理由同建議一致 —— static mode 讀嘅 JSON 本身就係
Python `downsample` 寫出嚟，所以應該係瀏覽器嗰邊跟 Python，唔係反過來。
`src/dashboard/builder.py` 同 `src/api/service.py` 嘅取樣**一行都冇改**。

### 改動

1. **`frontend/src/lib/downsample.ts`** —— 新增 module-private `roundHalfToEven()`，
   取代 `Math.round`：

   ```ts
   const lower = Math.floor(value);
   const fraction = value - lower;
   if (fraction > 0.5) return lower + 1;
   if (fraction < 0.5) return lower;
   return lower % 2 === 0 ? lower : lower + 1;
   ```

   只會收到非負數（`i * step`，`i >= 0`、`step >= 0`），所以唔使處理負數個 case；
   `value - lower` 喺 2^52 以下係 IEEE-754 exact，所以 `=== 0.5` 呢個判斷同
   Python `round()` 對 double 嘅判斷係同一件事。呢兩點都寫咗喺 docstring 入面。

2. **`frontend/src/lib/downsample.test.ts`（新檔案）** —— cross-mode 測試：
   - 一張 `PYTHON_POSITIONS` 表，8 個 `(length, points)` 個案，expected indices
     **直接由 `_even_positions()` 讀出嚟**，包括票上舉嘅 `len=250, points=3`
     → `[0, 124, 249]`（`Math.round` 會出 125）；
   - 每個個案**另加一條斷言**證明 `Math.round` 喺嗰個個案真係答錯 —— 冇呢條，
     日後有人改細張表、揀咗啲唔分歧嘅長度，測試會靜靜雞失去意義；
   - first / last / strictly increasing 不變式；
   - 一條「今日可見行為不變」嘅測試：所有 `length <= 600` 喺 `points=600` 之下原樣回傳。

3. **`src/api/service.py` —— `_even_positions()` docstring**
   補返票上點名講漏嗰句：static mode 嘅 TS 實作一樣受呢個 arithmetic 約束，
   **包括 rounding**，並寫明佢係人手 half-to-even 而唔係 `Math.round`，同點解。

### 驗證

- **Red**：未改 `downsample.ts` 之前跑新測試 —— 8 條 parity 斷言全部紅
  （assertion failure，唔係 collection error），另外 8 條「`Math.round` 真係答錯」
  同 2 條不變式測試綠。改完之後 18 條全綠。
- **窮舉 cross-mode 核對**：臨時 probe 掃 `2 <= total <= 250`、`1 <= points < total`
  共 **31,125 個組合**，兩邊各行一次、各累積一個 digest：

  | 實作 | digest |
  |---|---|
  | Python `_even_positions` | `901548278338682948` |
  | TS `downsample`（改完） | `901548278338682948` ✅ |
  | TS `downsample`（`Math.round`） | `1205094656943304447` ❌ |

  即係話改完之後兩邊喺呢個範圍內**逐個 index 完全一致**，而舊實作唔係。
  Probe 係一次性核對工具，已刪除（digest 係不透明數字，留低只會令測試難讀，
  委員會式斷言嘅價值低過上面嗰張具名個案表）。

- **今日前端行為不變**：`ActivityView.TRACK_POINTS = 600`，export `point_limit=600`，
  所以所有已存 track `length <= 600`，`downsample` 行 `n <= limit` 嗰條早返，
  **根本入唔到 rounding**。新測試有一條專門釘住呢點。原有嘅前端測試
  （包括 `src/data/static/source.test.ts` 嗰條「downsamples tracks on request and
  keeps first and last」）**一條都冇因為今次改動而要改**，行為不變；
  連新檔案計，前端 22 個 test file / 126 條測試全綠，`npm run lint`、
  `npm run typecheck` 綠。
