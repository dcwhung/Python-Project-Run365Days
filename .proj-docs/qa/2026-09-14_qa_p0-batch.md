#### CUI-0001 非有限值繞過 W-005，令 static 同 api 兩個部署目標對同一份輸入產生唔同結果

W-005 為 `optional_float` / `optional_int` 加咗 `math.isfinite()`，
但 `src/activities/parsers/tcx.py:106-107` 兩個**必填**數值行嘅係裸 `float(required_text(...))`，
而 `src/export/records.py:64-72` 嘅 `_round()` 只擋 NaN 唔擋 ±inf。四個後果：

| 輸入 | parse_all | static | sqlite | GraphQL |
|---|---|---|---|---|
| `DistanceMeters=inf` | 成功，`distance_km=inf` | **crash** | 成功，存 `inf` | 成句 query 死 |
| `TotalTimeSeconds=inf` | **`OverflowError` 整個中止** | — | — | — |
| `DistanceMeters=nan` | 成功，**靜默變 0.0** | 成功（錯數） | 成功（錯數） | 回錯數 |
| `TotalTimeSeconds=nan` | 成功，**靜默變 0** | 成功（錯數） | 成功（錯數） | 回錯數 |

`OverflowError` 係 `ArithmeticError` 子類，唔係 `ValueError`，所以 W-004 收窄後嘅
`except ValueError` 接唔到，一個壞檔案拉冧成次 export。

**點解評 Major 而唔係 Critical**：
(a) 現時**唔可達** —— 365 個真實檔案全部乾淨，static JSON 同基準 byte-identical；
(b) **唔係回歸** —— 基準 `1896778` 嘅 `contextlib.suppress(ValueError, AttributeError, ET.ParseError)`
同樣接唔到 `OverflowError`，而且 `_lap_row` 同樣無防護，基準只係更差；
(c) 失敗係響亮嘅（CI 會紅），唔會靜默出貨壞資料 —— 除咗 `nan` 靜默變 0 嗰兩行。

#### CUI-0002 AU-003 改用 zoneinfo 後未宣告 tzdata，而 pytz 變成死依賴

`pytz` 自帶 tz database，`zoneinfo` 唔帶（讀 system `/usr/share/zoneinfo`，
否則 fallback `tzdata` PyPI package）。`pyproject.toml` 仍然宣告已經零使用嘅 `pytz`，
且**完全冇宣告 `tzdata`**。實測：

```
$ PYTHONTZPATH="" python3 -c "from run365days.common.time import parse_datetime; parse_datetime('2021-10-17 06:10:56')"
RAISED: ZoneInfoNotFoundError 'No time zone found with key Asia/Hong_Kong'
# 同一條件下基準（pytz）: OK: 2021-10-17 06:10:56+07:37
```

兩個 CI 目標現時唔受影響（`ubuntu-latest` 有 system tzdata）。
Vercel Python runtime 有冇，喺 checkout 入面驗證唔到。
風險環境：Windows 開發機、slim / distroless container。
