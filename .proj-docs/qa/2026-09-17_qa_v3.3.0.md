## 4. 主動測試（新寫 case，非既有測試）

> **點解要做**：兩位 reviewer 加埋驗咗 19 格 wire，**全部用 literal argument**。
> Literal 同 variable 喺 graphql-core 係兩條唔同嘅 coercion 路徑。以下係 literal 到唔到嘅地方。

### A1 — Bounds argument 經 **variable** 而唔係 literal（**全新覆蓋**）

| Document | Variables | `argument` | `code` | allowlist |
|---|---|---|---|---|
| `query Q($l: Int!) { activities(limit: $l) { id } }` | `{l: -5}` | **`limit`** | `ARGUMENT_OUT_OF_RANGE` | ✅ |
| `query Q($o: Int!) { activities(offset: $o) { id } }` | `{o: -1}` | **`offset`** | 同上 | ✅ |
| `query Q($l,$o) { activities(limit: $l, offset: $o) }` | `{l:-5,o:-1}` | **`limit`**（fail-fast 一致） | 同上 | ✅ |
| `query Q($p: Int!) { activity(id:"v0"){ track(points:$p) } }` | `{p: 0}` | **`points`**，`path=['activity','track']` | 同上 | ✅ |

**Variable 路徑同 literal 路徑行為一致，冇缺口。** 呢條路之前冇人驗過。

### A2 — GraphQL `Int` 係 32-bit signed，過界會點？（**全新覆蓋**）

| 輸入 | 結果 | `extensions` |
|---|---|---|
| `offset: 2147483648`（literal） | `Int cannot represent non 32-bit signed integer value` | **`{}`** ✅ |
| `offset: 2147483648`（variable） | `Variable '$o' got invalid value …` | **`{}`** ✅ |
| `offset: 2147483647`（剛好合法） | **成功**，`data: {"activities": []}` | — |
| `limit: -2147483648`（int32 最細） | bounds refusal | `{code, argument:"limit"}` ✅ |

**分類正確**：coercion 喺 resolver 之前，冇 argument 可以 name，所以 `extensions` 空 —— 呢個正正係
`REFUSAL_ARGUMENT_KEY` docstring 劃嗰條線。**冇 off-by-one：`2**31-1` 過，`2**31` 唔過。**

### A3 — 一個 document 入面多條 list field 同時越界（**全新覆蓋**）

```
{ activities(limit: 0) { id } weight(limit: 1001) { date }
  weather(offset: -2) { date } warnings(limit: -9) { date } }
→ errors = 1     （只有 activities / limit）     data = null
```
