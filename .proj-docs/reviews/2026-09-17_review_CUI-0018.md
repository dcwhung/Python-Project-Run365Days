### 裁決 3 — Bounds 得一個 code ⚠️ **結論可接受，但理由書有一句係假嘅 → W-035**

「三個 argument 上下兩頭補救全部一樣」呢半成立：`limit` / `offset` / `points` 超界，補救都係「改個值，原封不動 retry 冇用」。

但第二半 —— 「`path`/`locations`（CUI-0037 已令佢哋 load-bearing）已經指到邊個 field **邊個 argument**」—— **實測唔成立**。我起咗個 probe 逐個 bounds document 打印 `path` / `locations`，再用 column 反查文件字元：

```
DOC: { activities(limit: 1000, offset: -1) { id } }
  message  : offset must not be negative, got -1
  path     : ["activities"]
  locations: [{"line": 1, "column": 3}]
  char at col 3: 'activities(limit: 1000, of'      ← 指住 field name，唔係 `offset: -1`

DOC: { activities(limit: 0) { id } }
  path     : ["activities"]
  locations: [{"line": 1, "column": 3}]
  char at col 3: 'activities(limit: 0) { id '

DOC: { activity(id: "r0") { track(points: 0) { sec } } }
  path     : ["activity", "track"]
  locations: [{"line": 1, "column": 24}]
  char at col 24: 'track(points: 0) { sec } }'      ← 一樣係 field name
```

成因清楚：`ClientRefusalError.__init__` 傳嘅係 `nodes=raw.field_nodes`，即**field node**，所以 `locations` 永遠指 field 開頭，唔會指 argument。

**影響有分別，要講清楚**：
- 對 `track` —— `path` 係 `["activity","track"]`，而 `track` 得一個有界 argument（`points`），所以 path **實際上**唯一決定咗係邊個 argument。**呢度 lane 講得啱。**
- 對四條 list field（`activities` / `weight` / `weather` / `warnings`）—— 每條有**兩個**有界 argument（`limit` 同 `offset`），而一次只會 raise 一個。client 收到 `ARGUMENT_OUT_OF_RANGE` + `path: ["activities"]`，**冇任何結構化資料話俾佢知係 `limit` 定 `offset`**，只能返去 parse `message` —— **正正係 CUI-0018 (a) 要廢除嘅行為**。

詳見 **W-035**。
