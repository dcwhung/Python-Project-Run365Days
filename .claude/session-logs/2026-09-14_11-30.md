## 兩個關於「工具唔等於保護」嘅發現

### 1. 開咗個 linter，唔代表佢捉到

`eslint-plugin-jsx-a11y` 嘅 `recommended` **同** `strict` **都只捉到 5 個違規入面 1 個**。
原因：`aria-query` 俾 `<tr>` / `<td>` / `<th>` 派咗 interactive 嘅 `row` / `cell` role，
所以 `click-events-have-key-events` / `no-noninteractive-element-interactions` / `interactive-supports-focus`
三條全部行過一個可點擊嘅 row 都唔出聲。

**Main agent 用最小 probe 獨立重現**：`jsx-a11y strict` 對裸 `<tr onClick>` → exit 0，零 output。
解法：喺 plugin 之上加 `no-restricted-syntax` selector。

### 2. 改動會令 guard 測試**靜靜變成空殼**

`tests/test_api.py` 嗰條 `assert len(loaded) <= 2 * points`（靠 `loaded_as_persistent` ORM event）
喺改用 Core select 之後 event **一次都唔 fire**，斷言變成 `0 <= 10` —— **照樣綠，但乜都冇量度緊**。

CUI-0029 嘅解法值得複製：**同時量兩樣嘢，而且用同一個 session 先校準兩個計數器再信佢哋**。
校準步驟先讀全條 track、斷言兩個計數器都動咗預期數量。**一個停止報數嘅儀器會大聲失敗，
而唔係靜靜俾斷言過關。**

> 兩者共通：**冇人量度過個工具實際捉唔捉到。** 任何新 gate 落地時都要做 mutation check。
> ⚠️ Mutation check 本身都要驗：我做過一次 `sed` pattern 唔 match（多打咗 `: int`），
> mutation 根本冇發生，差啲將「測試全綠」當成結果。**一個冇 assert 過「mutation 真係落咗」嘅 mutation test 係無效嘅。**
